1. Software Testing

Software testing is the process of evaluating software to find defects and verify that it satisfies specified requirements.

Testing helps identify defects before software is delivered to users.

2. Objectives of Testing

  • Find defects.
  • Verify requirements.
  • Improve software quality.
  • Check reliability.
  • Reduce the risk of failures.
  • Ensure expected behavior.

3. Verification and Validation

Verification Validation
Checks whether software is being built correctly. Checks whether the right software is being built.
Focuses on documents and development activities. Focuses on the actual software and user needs.

4. Levels of Testing

  1. Unit Testing
  2. Integration Testing
  3. System Testing
  4. Acceptance Testing

5. Unit Testing

Unit testing tests individual modules or components of software independently.

Example: Testing a login function separately.

6. Integration Testing

Integration testing checks whether different modules work correctly when combined.

Example: Checking whether the login module correctly connects with the user database.

7. System Testing

System testing evaluates the complete integrated software system against its requirements.

8. Acceptance Testing

Acceptance testing determines whether the software is acceptable to the customer or intended users.

9. Black Box Testing

Black box testing tests software functionality without requiring knowledge of its internal implementation.

Examples:

  • Equivalence Partitioning
  • Boundary Value Analysis
  • Decision Table Testing
  • State Transition Testing

10. White Box Testing

White box testing examines internal program logic, structure and control flow.

Examples:

  • Statement Coverage
  • Branch Coverage
  • Path Testing
  • Condition Testing

11. Black Box vs White Box Testing

Black Box White Box
Internal code is not required. Internal code structure is considered.
Focuses on functionality. Focuses on logic and control flow.
Usually based on requirements. Usually based on program structure.

12. Test Case

A test case is a documented set of inputs, conditions and expected results used to verify a particular software behavior.

Typical fields:

  • Test Case ID
  • Test Description
  • Input
  • Expected Result
  • Actual Result
  • Status

13. Test Plan

A test plan is a document that describes the testing scope, strategy, resources, schedule and activities.

14. Debugging

Debugging is the process of locating, analyzing and fixing defects in software.

Testing identifies failures or defects; debugging investigates and fixes the underlying problems.

15. Regression Testing

Regression testing checks that changes or fixes have not introduced new problems into previously working functionality.

16. Performance Testing

Performance testing evaluates software behavior under expected and specified workloads.

Examples:

  • Load Testing
  • Stress Testing
  • Scalability Testing
