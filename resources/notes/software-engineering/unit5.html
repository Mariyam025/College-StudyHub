1. Software Maintenance

Software maintenance is the process of modifying and updating software after delivery to correct problems, improve performance or adapt it to changed requirements and environments.

2. Types of Software Maintenance

  • Corrective Maintenance
  • Adaptive Maintenance
  • Perfective Maintenance
  • Preventive Maintenance

3. Corrective Maintenance

Corrective maintenance fixes defects and errors discovered after software deployment.

Example: Fixing a login error reported by users.

4. Adaptive Maintenance

Adaptive maintenance modifies software so that it continues to work in a changed environment.

Example: Updating software to work with a new operating system.

5. Perfective Maintenance

Perfective maintenance improves existing software by adding enhancements or improving performance and usability.

Example: Adding a new search feature to an existing application.

6. Preventive Maintenance

Preventive maintenance makes changes intended to reduce the possibility of future problems and improve maintainability.

7. Maintenance Process

  1. Identify change request.
  2. Analyze the requested change.
  3. Plan the modification.
  4. Implement the change.
  5. Test the modified software.
  6. Deploy the updated software.
  7. Update documentation.

8. Software Configuration Management

Software Configuration Management (SCM) is the process of identifying, organizing and controlling changes to software and related artifacts.

Activities:

  • Configuration Identification
  • Version Control
  • Change Control
  • Configuration Status Accounting
  • Configuration Auditing

9. Version Control

Version control records changes to files so that different versions can be managed and previous versions can be restored when required.

Example: Git is a widely used version control system.

10. Change Management

Change management is the systematic process of evaluating, approving and implementing changes in a software project.

Basic steps:

  1. Submit change request.
  2. Analyze impact.
  3. Approve or reject change.
  4. Implement approved change.
  5. Test the change.
  6. Document the change.

11. Software Risk

A software risk is an uncertain event or condition that may negatively affect a software project's cost, schedule, scope or quality.

Examples:

  • Requirement changes
  • Technical problems
  • Resource shortage
  • Schedule delays
  • Security problems

12. Risk Management

Risk management involves identifying, analyzing, planning responses to and monitoring project risks.

Steps:

  1. Risk Identification
  2. Risk Analysis
  3. Risk Planning
  4. Risk Monitoring

13. Project Estimation

Software project estimation predicts the effort, cost, time and resources required to complete a project.

Common estimation areas:

  • Effort
  • Cost
  • Schedule
  • Resources

14. Software Metrics

Software metrics are quantitative measures used to evaluate software, processes or projects.

Examples:

  • Lines of Code
  • Defect Count
  • Test Coverage
  • Development Effort
  • Project Duration

15. Software Quality Assurance

Software Quality Assurance (SQA) is a planned and systematic approach to ensuring that software processes and products meet defined quality requirements.

SQA activities:

  • Reviews
  • Audits
  • Testing
  • Process monitoring
  • Quality measurement

16. Project Scheduling

Project scheduling determines the tasks, sequence, duration and timing required to complete a project.

Important elements:

  • Tasks
  • Milestones
  • Dependencies
  • Deadlines
  • Resources

17. Gantt Chart

A Gantt chart is a visual representation of project tasks against time. It helps in planning and tracking project progress.

18. Software Documentation

Software documentation contains information about the software, its development, usage, maintenance and technical details.

Types:

  • Requirement Documentation
  • Design Documentation
  • User Documentation
  • Technical Documentation
  • Maintenance Documentation

19. Importance of Software Maintenance

  • Fixes defects.
  • Improves performance.
  • Adapts software to new environments.
  • Adds new functionality.
  • Improves security.
  • Extends software life.
