1. What is Software?

Software is a collection of programs, procedures and related data that tells a computer how to perform specific tasks.

Examples include operating systems, mobile applications, web applications and games.

2. What is Software Engineering?

Software Engineering is the systematic and disciplined approach to the development, operation, maintenance and testing of software.

Simple Definition: Software Engineering means developing software in a systematic, organized and efficient way.

3. Need for Software Engineering

As software systems become larger and more complex, proper engineering practices are needed to develop reliable software.

Main needs:

  • To manage large software projects
  • To reduce development cost
  • To complete projects within time
  • To improve software quality
  • To reduce errors
  • To make software easier to maintain
  • To satisfy user requirements

4. Characteristics of Good Software

  • Correctness
  • Reliability
  • Efficiency
  • Usability
  • Maintainability
  • Security
  • Portability
  • Flexibility

5. Software Crisis

Software crisis refers to the difficulties faced during the development of large and complex software systems.

Problems of software crisis:

  • Projects taking too much time
  • High development cost
  • Frequent software failures
  • Poor quality
  • Difficult maintenance
  • Not meeting user requirements

6. Software Engineering Principles

  • Plan before development
  • Understand user requirements
  • Maintain simplicity
  • Test software properly
  • Document the software
  • Design for maintainability
  • Manage project risks

7. Software Process

A software process is a set of activities used to develop, deliver and maintain software.

Major activities:

  1. Requirement Analysis
  2. Design
  3. Implementation
  4. Testing
  5. Deployment
  6. Maintenance

8. Software Development Life Cycle (SDLC)

SDLC is a systematic process used to develop software from the initial idea to maintenance.

Phases of SDLC:

  1. Planning
  2. Requirement Analysis
  3. System Design
  4. Implementation / Coding
  5. Testing
  6. Deployment
  7. Maintenance
SDLC helps in developing software in a structured and organized manner.

9. Requirement Engineering

Requirement Engineering is the process of identifying, analyzing, documenting and managing the requirements of users and the system.

Main activities:

  • Requirement Elicitation
  • Requirement Analysis
  • Requirement Specification
  • Requirement Validation
  • Requirement Management

10. Functional Requirements

Functional requirements describe what the system should do.

Example:

  • User should be able to login.
  • User should be able to register.
  • Admin should be able to add notes.
  • Student should be able to search notes.

11. Non-Functional Requirements

Non-functional requirements describe the quality attributes and constraints of a system.

Examples:

  • Performance
  • Security
  • Reliability
  • Usability
  • Scalability
  • Maintainability

12. Functional vs Non-Functional Requirements

Functional Non-Functional
Describes what the system does. Describes how well the system works.
Related to system functionality. Related to quality and constraints.
Example: Login. Example: Security.

13. Feasibility Study

A feasibility study determines whether a proposed software project is practical and achievable.

Types:

  • Technical Feasibility
  • Economic Feasibility
  • Operational Feasibility
  • Schedule Feasibility
  • Legal Feasibility

14. Software Project Management

Software Project Management involves planning, organizing, monitoring and controlling software development activities.

Important areas:

  • Project Planning
  • Cost Estimation
  • Time Management
  • Risk Management
  • Team Management
  • Quality Management

15. Software Quality

Software quality refers to how well software satisfies its specified requirements and user expectations.

Quality factors:

  • Correctness
  • Reliability
  • Efficiency
  • Usability
  • Maintainability
  • Security
