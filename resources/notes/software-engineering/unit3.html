1. Software Design

Software design is the process of defining the architecture, components, interfaces and data of a software system.

Design describes how the software will be built before actual coding.

2. Objectives of Software Design

  • Convert requirements into a software structure.
  • Provide a clear system architecture.
  • Reduce complexity.
  • Improve software quality.
  • Make software easier to maintain.
  • Support testing and implementation.

3. Design Principles

  • Abstraction
  • Modularity
  • Information Hiding
  • Low Coupling
  • High Cohesion
  • Separation of Concerns

4. Abstraction

Abstraction means representing only the important features of a system while hiding unnecessary implementation details.

Example: A user can use an ATM without knowing its internal software implementation.

5. Modularity

Modularity means dividing a large software system into smaller, manageable modules.

Benefits:

  • Easy development
  • Easy testing
  • Easy maintenance
  • Better organization

6. Coupling

Coupling represents the degree of dependency between software modules.

Lower coupling generally makes a system easier to modify and maintain.

Types:

  • Data Coupling
  • Stamp Coupling
  • Control Coupling
  • Common Coupling
  • Content Coupling

7. Cohesion

Cohesion represents how closely related the responsibilities of a module are.

High cohesion is generally desirable because a module focuses on closely related tasks.

8. Coupling vs Cohesion

Coupling Cohesion
Relationship between modules. Relationship among elements inside a module.
Lower coupling is generally preferred. Higher cohesion is generally preferred.

9. Software Architecture

Software architecture describes the high-level organization of a software system and the relationships between its major components.

Examples:

  • Layered Architecture
  • Client-Server Architecture
  • Three-Tier Architecture
  • Microservices Architecture

10. User Interface Design

User Interface Design deals with designing the way users interact with software.

Good UI should be:

  • Simple
  • Consistent
  • Easy to understand
  • Responsive
  • Accessible

11. Database Design

Database design defines how data is organized, stored and related within a database system.

Important concepts:

  • Tables
  • Fields
  • Primary Keys
  • Foreign Keys
  • Relationships

12. Design Documentation

Design documentation records the technical design decisions and structure of a software system.

  • Architecture diagrams
  • Data design
  • Interface design
  • Module descriptions
  • Database design
