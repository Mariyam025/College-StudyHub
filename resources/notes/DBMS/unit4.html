Database Management System

Unit 4 - Normalization and Transaction Processing

1. Functional Dependency

A functional dependency describes a relationship where one attribute determines another attribute.

Example: Student_ID → Student_Name

2. Normalization

Normalization is the process of organizing database tables to reduce redundancy and avoid data anomalies.

First Normal Form (1NF)

A table is in 1NF when each field contains atomic values and there are no repeating groups.

Second Normal Form (2NF)

A table in 2NF is in 1NF and has no partial dependency on a composite key.

Third Normal Form (3NF)

A table in 3NF is in 2NF and has no transitive dependency.

BCNF

Boyce-Codd Normal Form is a stronger form of normalization where every determinant is a candidate key.

3. Inclusion Dependency

An inclusion dependency specifies that values of one attribute or set of attributes must also occur in another relation.

4. Lossless Join Decomposition

A decomposition is lossless when joining the decomposed tables produces the original information without losing data.

5. FD, MVD and JD

  • FD: Functional Dependency
  • MVD: Multivalued Dependency
  • JD: Join Dependency

6. Transaction Processing

Transaction: A transaction is a sequence of database operations treated as one logical unit of work.

Example

Bank transfer: Debit money from one account and credit it to another. Both operations should be completed correctly.

7. Serializability

Serializability checks whether the result of concurrent transactions is equivalent to some serial execution.

Conflict Serializable Schedule

A schedule is conflict serializable if it can be transformed into a serial schedule by swapping non-conflicting operations.

View Serializable Schedule

A schedule is view serializable when it is view-equivalent to a serial schedule.

8. Recoverability

A schedule is recoverable when transactions commit only after the transactions whose data they have read have committed.

9. Recovery from Transaction Failure

Recovery techniques restore the database to a consistent state after transaction failures.

10. Log-Based Recovery

A log records database operations. It can be used to undo or redo operations during recovery.

11. Checkpoints

A checkpoint saves a known consistent point in the database system and helps reduce recovery time.

12. Deadlock Handling

Deadlock occurs when transactions wait for each other indefinitely. DBMS can use prevention, avoidance or detection/recovery techniques.

Quick Revision:
  • Normalization reduces redundancy.
  • 1NF → atomic values.
  • 2NF → removes partial dependency.
  • 3NF → removes transitive dependency.
  • BCNF → stronger normal form.
  • Transaction = logical unit of work.
  • Serializability ensures correct concurrent execution.
  • Logs and checkpoints help recovery.
