Database Management System

Unit 5 - Concurrency Control Techniques

1. Concurrency Control

Definition: Concurrency control is used to manage simultaneous transactions so that database consistency is maintained.

When many users access a database at the same time, concurrency control helps prevent incorrect results and conflicts.

2. Locking Techniques

Locking controls access to database items while transactions are executing.

Shared Lock

A shared lock generally allows reading of a data item by multiple transactions.

Exclusive Lock

An exclusive lock is used when a transaction wants to modify a data item.

Shared Lock Exclusive Lock
Used for reading Used for writing/modification
Multiple shared locks may coexist Conflicts with other locks when required

3. Two-Phase Locking

Two-phase locking divides locking into two phases.

  • Growing Phase: Locks can be acquired.
  • Shrinking Phase: Locks can be released.

4. Timestamp Protocol

A timestamp protocol assigns each transaction a timestamp and uses it to maintain an order of transaction execution.

Older and newer transactions are ordered using their timestamps and operations are allowed according to the protocol rules.

5. Validation-Based Protocol

Validation-based concurrency control allows transactions to execute without locking during their initial phase and checks for conflicts before committing.

Phases

  1. Read Phase: Transaction reads data and performs calculations.
  2. Validation Phase: System checks for conflicts.
  3. Write Phase: Changes are written if validation succeeds.

6. Comparison

Technique Main Idea
Locking Controls access using locks
Timestamp Uses transaction timestamps
Validation Checks conflicts before writing

7. Importance of Concurrency Control

  • Maintains database consistency
  • Prevents conflicting operations
  • Controls simultaneous transactions
  • Helps maintain correct transaction execution
Quick Revision:
  • Concurrency control manages simultaneous transactions.
  • Shared lock is mainly used for reading.
  • Exclusive lock is used for modification.
  • Timestamp protocol uses transaction timestamps.
  • Validation protocol checks conflicts before committing.
