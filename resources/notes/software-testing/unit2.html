Software Testing - Unit 2

1. Dynamic Testing

Dynamic Testing is testing performed by executing the software and observing its actual behaviour.
Example: Opening a website, entering a username and password, clicking Login and checking the result.

2. Major Dynamic Testing Techniques

  • Black Box Testing
  • White Box Testing

3. Black Box Testing

Black Box Testing tests the external behaviour of software without requiring knowledge of its internal source code.

The tester focuses on inputs, outputs and requirements.

Example:
A tester enters a username and password into a login page and checks whether login succeeds or fails. The tester does not need to know the internal JavaScript or Java code.

Advantages

  • Does not require knowledge of internal code.
  • Focuses on user requirements.
  • Can be performed from the user's point of view.
  • Useful for functional testing.

Limitations

  • Internal code paths may remain untested.
  • Complete coverage is difficult.
  • Good test cases require a clear understanding of requirements.

4. White Box Testing

White Box Testing tests the internal structure, logic, code paths and implementation of a program.
Example: A developer examines whether every branch of an if-else statement has been executed during testing.

Advantages

  • Examines internal logic.
  • Helps identify coding errors.
  • Can measure code coverage.
  • Useful for detecting unreachable code.

Limitations

  • Requires programming knowledge.
  • Can be time-consuming for large programs.
  • Cannot by itself verify whether requirements are correct.

5. Black Box vs White Box Testing

Black Box White Box
Internal code is not required. Internal code is examined.
Focuses on functionality. Focuses on internal logic.
Based mainly on requirements. Based mainly on code structure.
Tester may not need programming knowledge. Programming knowledge is generally required.

6. Equivalence Partitioning

Equivalence Partitioning divides input data into groups or classes where values are expected to behave similarly.

Instead of testing every possible input, one or more representative values are selected from each class.

Example

Suppose an application accepts age from 18 to 60.

Partition Range Example Test Value
Invalid Below 18 15
Valid 18 to 60 30
Invalid Above 60 70

This reduces the number of test cases while still testing representative input categories.

7. Boundary Value Analysis

Boundary Value Analysis (BVA) focuses on values at and around the boundaries of valid input ranges.

Many errors occur near boundaries, so these values are important for testing.

Example

Suppose valid age is 18 to 60.

Important test values include:

  • 17 - just below minimum
  • 18 - minimum
  • 19 - just above minimum
  • 59 - just below maximum
  • 60 - maximum
  • 61 - just above maximum
Easy Trick:
For a range 18–60, think around both boundaries: 17, 18, 19 and 59, 60, 61.

8. Equivalence Partitioning vs Boundary Value Analysis

Equivalence Partitioning Boundary Value Analysis
Divides input into classes. Focuses on boundary values.
Tests representative values. Tests values near limits.
Reduces test cases. Helps find boundary-related defects.

9. Decision Table Testing

Decision Table Testing is a technique used when the output depends on combinations of conditions.

A decision table represents conditions and corresponding actions in tabular form.

Example: Login

Username Valid? Password Valid? Expected Action
Yes Yes Allow Login
Yes No Show Password Error
No Yes Show Username Error
No No Show Login Error

Advantages

  • Handles combinations of conditions.
  • Provides systematic test coverage.
  • Easy to understand.
  • Useful for business rules.

10. State Transition Testing

State Transition Testing checks how a system changes from one state to another when events or inputs occur.
Example: An ATM may have states such as:

Card Inserted → PIN Entered → Account Verified → Transaction → Card Removed

Uses

  • Login systems
  • ATM systems
  • Order processing
  • Mobile applications
  • Workflow systems

11. Error Guessing

Error guessing is an experience-based technique where testers predict likely errors based on previous experience.

Example:
  • Entering empty fields
  • Entering special characters
  • Entering very large values
  • Using incorrect formats
  • Submitting a form multiple times

12. White Box Testing Techniques

Important white box techniques include:

  • Statement Coverage
  • Branch Coverage
  • Condition Coverage
  • Path Testing
  • Data Flow Testing

13. Statement Coverage

Statement coverage measures whether the executable statements of a program have been executed by the test cases.
Statement Coverage = (Number of Executed Statements / Total Statements) × 100
If a program contains 20 executable statements and tests execute 18, then coverage = (18/20) × 100 = 90%.

14. Branch Coverage

Branch coverage checks whether different decision outcomes have been executed.

For:

if (age >= 18)

both outcomes should be tested:
1. Condition True
2. Condition False

15. Condition Coverage

Condition coverage checks whether the individual conditions in decision expressions have evaluated to both true and false where applicable.

16. Path Testing

Path Testing is a white box technique that identifies and tests execution paths through a program.
Example:

Start → Input → Condition → True/False → Output → End

The objective is to execute important independent paths through the program.

17. Control Flow Graph

A Control Flow Graph (CFG) represents the flow of control in a program.

It contains:

  • Nodes: Statements or blocks of statements.
  • Edges: Flow of control between nodes.

18. Cyclomatic Complexity

Cyclomatic Complexity is a software metric used to measure the number of linearly independent paths in a program's control flow graph.
V(G) = E - N + 2

Where:

  • E = Number of edges
  • N = Number of nodes

For a connected control flow graph, another common form is:

V(G) = Number of decision nodes + 1
If a program contains 3 independent decision points, cyclomatic complexity = 3 + 1 = 4.

19. Graph Matrix

A graph matrix represents relationships between nodes of a control flow graph using a matrix structure.

It can help in analyzing connections and paths in a program.

20. Data Flow Testing

Data Flow Testing focuses on how variables are defined, used and modified during program execution.

Main Concepts

  • Definition: A value is assigned to a variable.
  • Use: The value of a variable is used.
  • Redefinition: A new value is assigned to the variable.
Example:

x = 10; → Definition of x
y = x + 5; → Use of x

21. Structural Testing

Structural testing examines the internal structure of the software. White box testing is a major form of structural testing.

22. Functional Testing

Functional testing checks whether the software performs the functions specified in its requirements.

Example: Testing whether an e-commerce website correctly adds a product to the shopping cart.

23. Structural vs Functional Testing

Functional Testing Structural Testing
Checks what the system does. Checks how the system works internally.
Usually associated with black box techniques. Usually associated with white box techniques.
Based on requirements. Based on code and control structure.

24. Quick Revision

  • Black box testing focuses on external behaviour.
  • White box testing focuses on internal code and logic.
  • Equivalence partitioning divides inputs into classes.
  • Boundary Value Analysis focuses on boundaries.
  • Decision tables test combinations of conditions.
  • State transition testing tests changes between states.
  • Error guessing uses tester experience.
  • Statement coverage checks executed statements.
  • Branch coverage checks decision outcomes.
  • Path testing checks execution paths.
  • Cyclomatic complexity helps determine independent paths.
  • Data flow testing follows variable definitions and uses.
